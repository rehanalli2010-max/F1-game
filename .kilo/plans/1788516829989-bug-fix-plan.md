# F1 Game - Bug Fix Plan

## Critical Bugs (Must Fix)

### 1. ReferenceError in AI Guest Car Update (ai.js:310)
**Location**: `js/ai.js` line 310 in `AICar.update()` remote guest branch
```javascript
this.physics.updateVehicle(this.vehicle, controls, dt, audioManager);
```
**Issue**: `audioManager` is not in scope - not passed as parameter or imported.
**Fix**: Pass `audioManager` to `AICar.update()` or access via `this.physics` / global reference.

### 2. Missing `finishTimeout` Cleanup in `clearAllTimers()` (session.js:497)
**Location**: `js/session.js` `clearAllTimers()` method
**Issue**: Only clears `gantryTimer`, not `finishTimeout`. If player switches sessions mid-race, the 15s finish timeout can fire incorrectly.
**Fix**: Add `finishTimeout` cleanup to `clearAllTimers()`.

### 3. Room Code Collision Retry Without Limit (network.js:104)
**Location**: `js/network.js` `hostRoom()` peer 'error' handler
```javascript
if (err.type === 'unavailable-id') {
  this.hostRoom(); // Recursive call without limit
}
```
**Issue**: Unbounded recursion on PeerJS ID collision can cause stack overflow.
**Fix**: Add retry counter with max attempts (e.g., 5).

### 4. Memory Leak in F1Car.dispose() (car.js:750)
**Location**: `js/car.js` `dispose()` method
**Issue**: Removes group from scene but doesn't dispose wheel meshes, geometries, materials in `wheelsGroup`, `frontWheelHolders`, `visualBody`.
**Fix**: Traverse and dispose all child meshes/geometries/materials before removing group.

### 5. Race Condition in Red Bull GLB Loading (car.js:424-487)
**Location**: `js/car.js` `_scheduleGlbBodySwap()` and `updateLivery()`
**Issue**: `updateLivery()` calls `_clearGlbBody()` and `buildVisualBody()` (which calls `_scheduleGlbBodySwap()`), but doesn't increment `_glbSwapRequestId`. A pending GLB load from before the livery change can still resolve and add itself to the scene.
**Fix**: Increment `_glbSwapRequestId` in `updateLivery()` before calling `buildVisualBody()`.

## High Priority Bugs

### 6. Ghost Collision State Not Reset Between Sessions (ai.js:857, session.js:121)
**Location**: `js/ai.js` `setupSession()` and `js/session.js` `startRaceSession()`
**Issue**: In single-player mode, `setupSession('RACE')` doesn't disable ghost collision because `this.isMultiplayer` is false. But if ghost mode was enabled in a previous multiplayer qualifying session, it persists.
**Fix**: Always call `physics.setGhostCollision(playerVehicle, aiCars[0].vehicle, false)` in `setupSession('RACE')` regardless of multiplayer state.

### 7. AI Overtaking Logic Uses Wrong Reference Frame (ai.js:385)
**Location**: `js/ai.js` `AICar.update()` line 385
```javascript
const rightVec = new THREE.Vector3(1, 0, 0).applyQuaternion(this.visualCar.group.quaternion);
```
**Issue**: Compares `carAheadLat` (car's local right) with `targetWp.normal` (track's left normal). These are different coordinate systems.
**Fix**: Use track-relative lateral offset from waypoint normal consistently, or transform car position to track frame.

### 8. Missing `getClosestTrackPoint` Implementation (circuit.js)
**Location**: Called throughout codebase (physics.js:295, main.js:400, timing.js:91, etc.)
**Issue**: Method not visible in provided circuit.js (output was truncated). If missing, will cause runtime errors.
**Fix**: Verify implementation exists in circuit.js (likely in truncated portion). If missing, add proper closest point calculation on spline.

## Medium Priority Bugs

### 9. Timer/State Not Fully Reset on Track Switch (main.js:1317, session.js)
**Location**: `js/main.js` `switchTrack()` and `js/session.js`
**Issue**: `switchTrack()` calls `session.initSession(PRACTICE)` but session state variables (`raceState`, `qualifyingPhase`, `playerRaceLap`, `jumpStart`, `leaderFinished`, `raceWinner`, `finishTimeout`) may retain stale values from previous race.
**Fix**: Add `resetSessionState()` method to SessionManager called on track switch.

### 10. Car Disposal Doesn't Clean Up Wheel Resources (car.js:750)
**Location**: `js/car.js` `dispose()`
**Issue**: Wheel meshes in `wheelMeshes`, `frontWheelHolders`, `wheelsGroup` geometries/materials not disposed.
**Fix**: Add disposal loop for all wheel-related Three.js objects.

### 11. Network: Unreliable DataChannel for Critical Game State (network.js:149)
**Location**: `js/network.js` `joinRoom()` connection options
```javascript
this.conn = this.peer.connect(targetPeerId, { reliable: false });
```
**Issue**: `reliable: false` uses UDP-like DataChannel - packets can be lost/dropped. Critical packets (INIT_GAME, STATE_SYNC) may not arrive.
**Fix**: Use `reliable: true` for initial handshake/game init, or implement acknowledgment/retry for critical packets.

### 12. Physics: Potential NaN in Velocity Calculations (physics.js:275-285)
**Location**: `js/physics.js` `updateVehicle()` cornering traction code
```javascript
const totalSpeed = Math.sqrt(body.velocity.x * body.velocity.x + body.velocity.z * body.velocity.z);
```
**Issue**: If velocity components are NaN (from previous frame corruption), this propagates. Guards exist at lines 91-96 but not before this calculation.
**Fix**: Add `Number.isFinite` check before `totalSpeed` calculation.

## Low Priority / Code Quality Issues

### 13. Mobile Touch Controls: Passive Event Listener Issue (main.js:346)
**Location**: `js/main.js` `initMobileControls()`
**Issue**: `touchstart`/`touchend` with `{ passive: false }` and `preventDefault()` may not prevent scrolling on iOS Safari.
**Fix**: Add `touch-action: none` CSS to touch buttons, or use `pointerdown`/`pointerup` events.

### 14. HUD: `drift-badge` Element ID Conflict (index.html:275, main.js:792)
**Location**: `index.html` line 275 and `main.js` line 792
```html
<div class="drs-badge" id="drift-badge" ...>DRIFT</div>
```
```javascript
const driftBadge = document.getElementById('drift-badge');
```
**Issue**: Element has class `drs-badge` but id `drift-badge`. CSS may not apply correctly. Also `drs-badge` class used for both DRS and drift.
**Fix**: Use separate IDs/classes: `drs-badge` for DRS, `drift-badge` for drift with distinct styling.

### 15. Qualifying Sector Detection Uses Hardcoded Progress Values (timing.js:113)
**Location**: `js/timing.js` `update()`
```javascript
if (progress >= 0.20 && progress <= 0.45 && !this.sector1Reached)
```
**Issue**: Sector boundaries hardcoded at 1/3 and 2/3 of lap. Won't work correctly for all track layouts.
**Fix**: Use track-defined sector split points from `trackData` or checkpoints.

### 16. Duplicate `getRaceWinner` Method (ai.js:1070 and 1168)
**Location**: `js/ai.js` lines 1070 and 1168
**Issue**: Two identical `getRaceWinner` methods in `AIGridManager` class.
**Fix**: Remove duplicate.

### 17. Lap Invalidation Threshold Hardcoded (timing.js:171)
**Location**: `js/timing.js` `onCompleteLap()`
```javascript
if (completedLapTime < 20.0) { ... }
```
**Issue**: 20s minimum only valid for Monza. Other tracks have different minimum realistic times.
**Fix**: Calculate minimum based on track length / max speed, or use track-specific config.
